# Zero Dashboard Predictions — Debug Transcript (2026-08-14)

## Symptom

Dashboard shows `pred_1d = 0.0`, `pred_5d = 0.0`, `pred_21d = 0.0` for the latest QQQ candle.

User quote: *"lol, so it should be both gives you both: raw blend immediately, then z-scoring kicks in at day 10. ok check why the dashboard shows zero and pls fix"*

## Root cause

The inference fix (deferred fix 2) replaced the z-score cold-start with a raw
0.5/0.5 blend so predictions are non-zero from the first candle. But the DB
still contained old predictions generated by the pre-fix code, and those old
predictions were all zeros. The scheduler recovers `last_processed_ts` from the
latest row in `equity_predictions`, so it skipped those candles.

The zero rows were for QQQ at:
- 2026-08-07 13:30 UTC
- 2026-08-10 13:30 UTC
- 2026-08-12 13:30 UTC
- 2026-08-13 13:30 UTC

## Fix steps

1. **Delete zero QQQ predictions** (from host, accessing the named Docker volume):
   ```bash
   sudo python3 - <<'PY'
   import sqlite3
   conn = sqlite3.connect('/var/lib/docker/volumes/deploy_data/_data/candles.db')
   c = conn.cursor()
   c.execute("""DELETE FROM equity_predictions
                WHERE symbol = 'QQQ'
                AND pred_1d = 0.0 AND pred_5d = 0.0 AND pred_21d = 0.0
                AND candle_ts >= (strftime('%s', 'now', '-10 days'))""")
   conn.commit(); conn.close()
   PY
   ```

2. **Ensure root-level model artifacts exist** for the engine:
   - `norm_stats_qqq_v1.json`
   - `qqq_tcn_v1.pt`
   - `qqq_lgbm_h1_v1.pkl`
   - `qqq_lgbm_h5_v1.pkl`
   - `qqq_lgbm_h21_v1.pkl`

   The per-symbol directories (`/models/QQQ/`, etc.) are used by the inference
   service; the engine still needs the flat root files for the QQQ model.

3. **Disable any exempted models** in `trading_models` if their files are gone:
   ```bash
   sudo python3 - <<'PY'
   import sqlite3
   conn = sqlite3.connect('/var/lib/docker/volumes/deploy_data/_data/candles.db')
   c = conn.cursor()
   c.execute("UPDATE trading_models SET enabled = 0 WHERE model_id = 'nvda-v1'")
   conn.commit(); conn.close()
   PY
   ```

4. **Restart the engine** so the backfill runs:
   ```bash
   cd /home/ubuntu/projects/MarketMoves/deploy
   docker-compose restart engine
   ```

## Related issues encountered during the fix

- **Engine crash on restart:** `norm_stats error for QQQ/PSQ: No such file or directory`.
  The engine could not find the flat root model files because the per-symbol
  zip bundle had been moved to `/models/QQQ/`. Copied the QQQ artifacts back
  to `/models/` root.

- **Engine crash on restart:** `norm_stats error for NVDA/NVDD: No such file or directory`.
  NVDA had been exempted and its files removed, but the `nvda-v1` row in
  `trading_models` was still `enabled=1`. Disabled the row.

- **Proxy transiently unhealthy:** during the restart loop, `mmn-proxy` became
  unhealthy. It recovered once the engine stabilized.

## Takeaways

- After any change that alters how predictions are generated, scan for and
  remove stale zero/NaN rows; otherwise the scheduler's `last_processed_ts`
  recovery will hide them from backfill.
- Keep the engine's flat root model files in sync with per-symbol inference
  bundles until the engine is updated to read per-symbol metadata directly.
- Exempting a model means disabling its registry entry, not just deleting its
  files.
